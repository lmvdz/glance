What this round is

This round re-scouted the tree with the same deep-module lens — small interfaces hiding real complexity, shallow seams, quiet defaults, information leakage — plus the candidates carried out of rounds 1–2's review ledgers. Two findings classes dominate: the daemon's remaining god-regions now have measured seams (the voice surface proves the target shape: 23 manager methods touching 12 fields over a 64-method coordinator), and the webapp has a class of green-but-unreachable surfaces that no gate can see because nothing scans webapp/ exports and tests keep dead symbols compiling.

Headline findings

A 305-line component and its 30-case suite render into nothing

webapp/src/components/hub/VoiceCallHud.tsx has zero production importers — its controls moved to Composer.tsx's icon row and the component was never deleted. The cascade is the real finding: the idle-hangup warning (idlePolicyLine, three copies including a live countdown) renders only inside this dead component, so the shipped 10-minute idle policy is invisible on screen while VoiceWorkspace.test.tsx keeps asserting the copy against a component nothing mounts. A green suite is pinning a surface that does not exist. → concerns 36, 35.

The idle toast tells a 3× lie

VoiceCallContext.tsx:407-409 fires shouldEndCallForIdle at 3 minutes (CALL_IDLE_TIMEOUT_MS, "Tightened 10min → 3min, Lars 2026-07-15") and then toasts "ended automatically after 10 minutes of inactivity." The tightening changed the constant and left the only string that reports it. Root cause is structural: two voice lanes (PTT vs room) mirror each other's policy with no shared boundary, so no string owns the number it names. → concern 36.

The projection-class table claims to be policy while four kinds route around it

projection-classes.ts lists 11 of 19 transcript-event kinds and falls back quiet-to-node — defensible. But the three voice kinds and token-burn-snapshot are emitted into the room by bespoke sites that never consult the table: the table is not wrong, it is bypassed. And doorSurface's default: "unit" is worse than the projection default — the webapp only synthesizes hrefs for plan/intervence, so a wrong default is a silently doorless card. → concern 32.

Refuted / corrected premises

  • "VoiceCallSession class extraction" — refuted. roomCall.ts holds no session state machine; every export is a pure (DTO, now) → copy/model function. The stateful session lives in VoiceCallContext.tsx (44 hooks) and useRoomCall.ts. The honest seam is a file split along the existing banner sections, driven by the 13-importer consumer table (38).
  • "IDLE_WARNING_MS was deleted as dead" — wrong; it lives (roomCall.ts:279) and its countdown copy ships — into the dead HUD. The gap is real but the mechanism is item 36's, not a missing constant.
  • "idle countdown never built" — it was built, orphaned, and is still tested. Worse than never-built.
  • Two spawn proposals share a name — the chat proposal (SpawnProposalCard with a working door) and the hub card (local:spawn-proposal, doorless, whose detail copy claims a wiring that does not exist). Only the hub path is dead (39).

A position paper · Long-horizon agent memory · July 2026

Memory is a ledger,
not a search problem

Multi-day agents rarely fail because retrieval is imprecise. They fail because their memory stores cannot say "this fact replaced that one." The fix happens at write time: an append-only ledger where facts are superseded, never deleted, and everything above it is a regenerated view.

#4821 07-12 09:41 decision  target = staging.api.internal SUPERSEDED → #5107
#5107 07-19 14:03 decision  target = prod.api.internal VALID since 07-19
#5211 07-21 03:22 worker-exit  unit-7f crashed; summary rebuilt from receipts RECONSTRUCTED

The core primitive. Struck, but still legible: invalidated facts stay addressable forever.

§1 · The misdiagnosis

"Vector soup" isn't about vectors

Two years of debate about the index: vectors, knowledge graphs, hybrid fusion. Meanwhile the failures that kill multi-day agents happen on the write path: facts superseded but never invalidated, workers dying before committing what they learned, summaries drifting until the original detail is unrecoverable.

Rank-by-relevance over a flat pool discards the three things a long-horizon agent needs:

Temporal orderwhich of these came last?
Supersessionwhich of these is still true?
Provenancewhat evidence produced this?
query: "which endpoint do we target?"
0.87 #4821  target = staging.api.internal  superseded 07-19
0.86 #5107  target = prod.api.internal  current
→ a flat store returns both at equal confidence; the model picks one

BM25 fails this the same way cosine similarity does. The problem is the schema, not the ranking.

Better retrieval over a corrupted store retrieves corruption faster.

§2 · The architecture

A ledger with regenerated projections

Independent lineages keep converging on one four-layer shape: TencentDB's L0–L3 pyramid, Graphiti/Zep's episode–entity split, MemGPT's tiers, and agent-runtime teams re-deriving it from their own outages.

L3 Active set What enters the prompt. Hard token budget (~800 — a discipline number, not physics; what matters is that one exists and is enforced), assembled and frozen at session start, prefix-stable. Precision over recall; must-see items surface by state, never by score.
↑ project (budgeted, filtered to currently-valid)
L2 Projections — summaries Regenerate, never append. Reference, never restate. Every abstraction keeps a drill-down pointer back to raw evidence.
↑ regenerate on every state transition, abnormal exits included
L1 Typed facts with validity Recurrence promotes, contradiction supersedes — and a human directive promotes on its own: commands arrive once, patterns arrive repeatedly. Model-observed facts always take the recurrence path. Each fact records when it became true and when it stopped; contradiction invalidates, never deletes. "What did we believe at time T?" is a filter, not archaeology.
↑ distill (through a single writer)
L0 Append-only exhaust Transcripts, tool outputs, receipts, gate logs. Owned by the runtime, not the model: written as a side effect of execution, surviving the death of any context window. Everything above is rebuildable from here.

Zep implements these semantics with a graph database, entity resolution, and LLM triple extraction. That cost fits a multi-tenant platform. A single runtime gets the same semantics from two fields and a write-path rule. Adopt the idea; skip the database. The entry side has a rule too: a fact is promoted by recurrence — observed repeatedly across sessions, with citations as receipts — not by a single model's decision to remember. Practitioners converge here independently: better a lagging memory that is never useless than an eager one that fills with noise.

Three settled rules for summaries

rule 1 Regenerate, never append Rebuild from ground truth on each transition. An appended summary has no recovery path: a poisoned turn becomes a permanent inheritance. Regeneration lets you drop it from history and rebuild. And regeneration is a gated loop: check the result against a declared list of must-survive-verbatim fields, retry a failing compression less aggressively, never ship it. One measured cliff (arXiv:2607.21503, not our fleet): 18,282 tokens crushed to 122 dropped task accuracy 66.7% to 57.1%.
rule 2 Reference, never restate A summary that quotes its sources is the log again, and the reason naive summarization grows without bound. Point at the plan doc, the PR, the log line.
rule 3 Keep drill-down pointers Each abstraction keeps an address back to raw evidence. When the summary proves too abstract, the exact flag or hash is one lookup away instead of gone.

The precise claim: not that context reduction is harmful. Lossy reduction helps in some regimes and hurts in others (arXiv 2606.00408), and you cannot know which per item in advance. So loss must be recoverable: compact aggressively, over a ground-truth layer regeneration can always reach back into.

Interlude · Human prior art

The night shift is a context window

Humans already run long-horizon agents. A hospital ward does multi-day, multi-worker, life-critical work with a total change of personnel every eight hours, and no nurse holds the patient in her head across the gap. The practices that make that safe are the four layers, arrived at under harsher penalties than token costs:

§3 · The real losses

Memory dies in the lifecycle, not the lookup

The exit path

spawn→ turn 1…n→ ✗ killed→ sweep reads receipts→ summary: RECONSTRUCTED→ next session consumes it
The context window died; the knowledge didn't, because L0 lives outside it.

A worker's context window is destroyed at exit, and anything uncommitted is orphaned. The orchestrator then resumes with a stale world-view and repeats paths that already failed. So the summary write belongs to the exit path itself, abnormal exits included: a sweep rebuilds a post-mortem summary from the receipts and marks it reconstructed, so it reads as evidence rather than self-report. An architecture that only captures clean exits is an architecture for demos.

Parallel writers

worker A 09:41 migration = complete SUPERSEDED at write
worker B 09:44 migration = rolled back CURRENT

Two workers will eventually assert contradictory facts, and a store without supersession serves both at equal confidence: non-determinism laundered as retrieval. Route durable writes through the single-writer supervisor and resolve at write time. One current assertion per subject; losers invalidated and still addressable. Consensus protocols solve the case where no supervisor exists. If you have one, use it.

Resolution alone is not sufficient. Agents adopt a conflicting memory at the first decision point where it appears, regardless of how it is presented; the measured effect is independent of labeling and placement, and stronger models lose more per event (arXiv 2607.10608, −2.1pp on a weak model to −25.5pp on a strong one). So superseded facts are excluded from the active set, not annotated. The exclusion is scoped to the action path: history stays addressable for audits and deliberate "why did we believe X" reads — run those in analysis contexts, never in the context that acts next.

§4 · Retrieval

Declared structure first. Lexical first. Vectors late.

Declared graph task refs · ownership · dependency edges — the runtime already emits them. Query them directly; they stay authoritative.
Inferred graph LLM triples + entity resolution + PageRank over your own exhaust: re-derives structure you already declared, then drifts from it.

GraphRAG and HippoRAG infer structure from unstructured text, and do it well. An agent runtime is not an unstructured corpus.

BM25 over validity-filtered stores→ log every miss→ classify the cause→ paraphrase misses > ~15%?→ then add a dense channel + RRF
Agent memory queries are dominated by exact identifiers: function names, flags, error strings, hashes. BM25's home turf, embedding-space quicksand.

Start lexical over structured, validity-filtered stores. Add a dense channel after logged misses prove that semantic paraphrase costs you. Infrastructure follows evidence. The split is regime-shaped, not tool-shaped: across five corpora (arXiv:2607.21503's study, not our fleet), keyword wins decisively where queries carry specific entities (0.815 vs 0.614) and dense wins decisively across wide semantic gaps (0.914 vs 0.290 on natural-language-to-code), with a measured 60–100× indexing tax for embeddings. So classify the misses by regime, and let the semantic-gap share decide.

§5 · Control points

The control point determines the mechanism

The model is the runtime It can page its own memory tiers mid-generation (MemGPT) or keep an in-window symbolic canvas. The mechanism lives inside the live context.
A supervisor at turn boundaries It never touches a live window. Its equivalents: spawn-time projection (assemble the active set when the worker starts) and exit-time reconciliation (harvest state when it ends).

Memory mechanisms assume a location for the intelligence, and they do not transplant across locations. Before asking whether a published mechanism works, ask where it assumes the control point is.

The control point also answers the standard objection to freezing: what about an urgent revocation mid-turn? The frozen prefix carries knowledge; the action gate carries authority. The layer that approves each tool call is never frozen — it takes revocations effective immediately, out-of-band, and blocks the very next action regardless of what the context believes. Advice may go a session stale; permission cannot. A kill-switch that depends on rewriting a prompt was never a kill-switch.

§6 · Evaluation

Score by error class, test with kill signals

Long-history QA benchmarks measure whether an agent can answer questions about the past. What matters is whether the next session acts correctly: the right tool, the exact flag, a constraint set days ago still honored. Score by failure class, because each class has a different architectural cause:

E_constraintViolated a rule established turns or days ago
E_contradictionReversed a finalized decision without instruction
E_hallucinationCited a past interaction that never happened
E_abstractionCompaction erased the exact identifiers work depends on
E_anachronismActed on a superseded fact as if current
E_pollutionWorker state leaked across an isolation boundary
E_orphanUncommitted knowledge died with its worker
E_driftRepeated re-summarization distorted the record
E_gov_haltRefused a valid action, citing a revoked constraint

Score constraints in both directions. A memory system that never breaches but constantly refuses is also broken — and it will game any harness that only counts breaches. So every probe set pairs active-constraint tasks (any breach fails the run) with revoked-constraint tasks (a spurious refusal is its own named failure). The sharpest probe shape: grant broadly, revoke the permission out-of-band while the agent is idle, jump the clock a week, wipe the context, then hand it a task that tempts the revoked power.

ingest→ ✗ kill→ T+1h resume→ ✗ kill→ T+24h resume→ ✗ kill→ T+1w resume
Injected clock, so no real days pass. Scored: does work continue without re-deriving settled decisions or re-executing completed steps?

Then probe the write path: kill workers mid-task and check their knowledge survived. Seed contradictions and check one fact wins, auditably. Demand an identifier that exists only in raw logs and check drill-down reaches it. Score the result as a vector, never an average — two classes are zero-tolerance (a single governance breach or lost identifier fails the run outright, whatever the aggregate says) — and record the divergence step: not just whether a resumed trajectory failed, but the first step where it left the rails, watched over a window of steps, because first-action-correct is not resumed-correctly. Memory that cannot survive a restart is a long conversation.

§7 · Rejected

What we strike from the ledger

  • Memory-as-a-platform for single-runtime agents — the semantics worth having cost two fields locally; the platform costs a network dependency and a second source of truth.
  • Inference layers over self-generated structure — re-deriving a graph the runtime already declared.
  • Hybrid retrieval as a default mandate — an optimization with a prerequisite (a proven semantic-miss rate), not a foundation.
  • Consensus engines where a supervisor exists — single-writer supersession is simpler, auditable, sufficient.
  • Unbudgeted "small" context blocks — a size discipline without a number is not a discipline.
  • Mechanism transplants across control points — in-window paging bolted onto supervisor architectures, and vice versa.
§8 · Falsifiability

How we'd know we're wrong

No architecture can be proven correct, only made falsifiable. Each claim is tested by flipping one seam on the same corpus of replayed real exhaust, where supersessions and worker deaths carry their own ground truth. Kill criteria are registered before any experiment runs:

№ClaimAblationStruck if
C1Supersession prevents stale-fact actionsvalidity-filtered vs flat storeanachronism errors don't drop ≥50%

C5Lexical-first sufficeslog real misses, classify causeparaphrase misses exceed ~15% — add the dense channel
C6Declared graph ≥ inferred graphdeclared refs vs LLM-inferred KG, same exhaustinferred wins multi-hop accuracy net of drift
C7Single-writer resolution sufficeswrite-time supersession vs both-facts-persistwrong-winner rate makes read-time arbitration safer
C8Frozen core beats live mutationfrozen-at-spawn vs mid-session updatesstaleness failures exceed consistency + cache wins
C9Superseded facts must be excluded, not annotatedprimer excluding vs including-with-labelslabeled-but-present performs no worse than excluded

Paired ablations at the seam, never system-vs-system. A validation program where no outcome could change the architecture is theater.

First data (2026-07-27, 36 pre-registered probes per experiment): a truly flat projection — two conflicting decisions, no validity metadata — is unanimously undeterminable to its consumer (12/12 refused to name a current target), while adding one supersession label yields 12/12 determined-correct, matching exclusion. The gap between a flat store and a ledger is, measurably, one field. A first run of the same experiment was voided before unblinding: its action-shaped probe was refused by the executing runtime's own safety gate — an unauthorized production action decided from untrusted context, blocked regardless of what the context asserted — which is §5's authority-at-the-gate principle demonstrating itself against the experiment designed to validate it.

The standing test is production. Count the error classes in real operation: settled decisions re-derived, humans correcting stale-fact actions, reconstructed summaries consumed by successors versus ignored. "Proven," in the only sense available, is when those counters trend to zero under adversarial probes and real load, after each kill criterion has had a fair chance to fire and didn't.

§9 · Case study

How glance fits

Glance is oversight for an autonomous engineering fleet: you glance, and you know. It is also the runtime this position was distilled from and tested against. Its daemon supervises at turn boundaries and never touches a worker's live context, which rules out in-window mechanisms by construction (§5). Its work graph is declared, so inference over its own exhaust is a category error it never has to make (§4).

Position → practice. DECIDED means written into the room-threads plan on 2026-07-25: schema and rules fixed before build. Four units merged 2026-07-27 (L1 supersession, the primer partition, the harness suite, the C5 counter), each through the same pipeline: worktree, full gates, blind adversarial review — which found real defects in every unit it flagged (an adopt race, a cap bypass, over-claiming test labels, a query-text leak) before they shipped. The pinning row spent a day RED first: applying the position's evaluation lens to its own runtime found the L3 rule unenforced at the primer. A case study that only turns rows green is a brochure; this one turns rows red, then earns them back.

The DECIDED rows are amendments this research forced into room-threads, the plan that rebuilds the room around nodes, where a node is the unit of work and the unit of conversation at once. Each closes one of §3's failure modes at design time: orphaned exits became abnormal exits regenerate too; parallel-writer disagreement became supersede, never coexist, with superseded cards addressable as history. The product's differentiation is that cards are proofs. Two live contradictory proofs is the one thing it can never render.

Glance is a good instrument for §8's program for two reasons. The replay corpus exists: months of receipts with real supersessions and real worker deaths in them, so C1 and C7 run against ground truth that needs no labeling. And the convergence is real: room-threads reached regenerate-never-append from its own scar tissue, a supervising session killed by context it could not shed, before anyone here read this literature. Two lineages, one conclusion.

Coda · Open problems

What nobody has solved

Live compaction of a moving target. Regeneration-on-transition sidesteps it for work with state boundaries; a months-long continuous goal with no settling points still lacks a principled compaction trigger. Skill distillation without drift. Turning noisy successful traces into reusable, parameterized procedures automatically; current summarization loses the exact parameters that made the trace work. Cross-runtime memory trust. When two agent systems share facts, provenance stops at the boundary; nothing today distinguishes "verified by their gates" from "their model said so."
